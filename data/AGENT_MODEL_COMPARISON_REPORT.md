# Agent与模型能力横向纵向对比分析报告

> 基于CVE漏洞修复基准测试的实证研究
>
> 数据来源：LiveCVEBench-io，189个CVE任务，31种Agent+模型组合

---

## 一、研究概述

本报告对比分析了4种代码Agent框架（terminus-2、mini-swe-agent、openhands、claude-code）与10种大语言模型在CVE漏洞修复任务上的表现，共计5,646次实验运行。

### 1.1 评估维度

- **成功率**: 漏洞是否被正确修复（通过测试验证）
- **效率**: 完成任务所需的轮次(turns)和Token消耗
- **鲁棒性**: 跨不同模型的一致性表现

### 1.2 Agent工作流概述

| Agent | 系统提示词长度 | 输出格式 | 核心特点 |
|-------|---------------|----------|----------|
| terminus-2 | ~315词 | JSON结构化 | 命令批处理，可配置等待时间 |
| mini-swe-agent | ~800词 | Markdown代码块 | 单命令/轮，THOUGHT推理 |
| openhands | ~2,400词 | 多工具调用 | task_tracker任务管理 |
| claude-code | - | 多工具调用 | Anthropic官方CLI |

### 2.2 效率对比

| Agent | 成功时平均轮次 | 失败时平均轮次 | 成功时平均Token | 失败时平均Token |
|-------|---------------|---------------|-----------------|-----------------|

**关键发现**：

- OpenHands的Token开销是terminus-2的**2.35倍**，但成功率反而低12%

### 2.3 Agent工作流详细对比

#### Terminus-2 工作流
```json
{
  "analysis": "分析当前终端状态，已完成什么，还需做什么",
  "plan": "下一步计划，每个命令的预期结果",
  "commands": [
    {"keystrokes": "ls -la\n", "duration": 0.1},
    {"keystrokes": "cat config.py\n", "duration": 0.1}
  ],
  "task_complete": false
}
```

**优势**：
- 命令批处理：单轮可执行多个命令
- 显式时间控制：防止命令超时或过早返回
- 结构化输出：便于解析和错误处理

#### Mini-SWE-Agent 工作流
```markdown
THOUGHT: 我需要先了解代码库结构，查看当前目录的文件...

```bash
ls -la
```
```

**优势**：
- 简单直观：易于模型遵循
- 推理透明：THOUGHT部分展示思考过程

**劣势**：
- 每轮仅1条命令：多步骤任务效率低
- 无批处理能力：文件探索耗时长

#### OpenHands 工作流
```
核心组件：
- ROLE: 明确助手角色定位
- EFFICIENCY: 强调操作合并
- FILE_SYSTEM_GUIDELINES: 文件操作规范
- CODE_QUALITY: 代码质量要求
- VERSION_CONTROL: Git操作规范
- PROBLEM_SOLVING_WORKFLOW: 5步问题解决流程
- TASK_MANAGEMENT: task_tracker工具使用
- SECURITY_RISK_ASSESSMENT: 安全风险等级(LOW/MEDIUM/HIGH)
```

**优势**：
- 全面的指导原则
- 内置任务分解能力

**劣势**：
- 提示词过长（2,400词），增加上下文负担
- 复杂指令需要强指令遵循能力
- 弱模型难以正确解析和执行

## 六、核心结论

### 6.1 Agent设计原则

1. **简洁优于复杂**：Terminus-2（315词提示）比OpenHands（2,400词）成功率高12.1个百分点

2. **批处理提升效率**：命令批处理使terminus-2比mini-swe减少23%的轮次

3. **结构化输出有益**：JSON格式便于解析、调试和错误恢复

### 6.2 模型选择建议

1. **首选Claude-4.5-Opus**：跨所有Agent达到27-42%成功率

2. **性价比选择**：MiniMax-M2 + terminus-2 (30.2%) 或 Gemini-3-Pro + terminus-2 (29.6%)

3. **避免的组合**：弱指令遵循模型 + OpenHands（如Qwen3 + OpenHands仅2.1%）

### 6.3 任务匹配建议

| 任务类型 | 推荐Agent | 原因 |
|----------|-----------|------|
| 简单单文件修复 | mini-swe-agent | 低开销，直接有效 |
| 多文件探索修复 | terminus-2 | 批处理加速探索 |
| 大型复杂项目 | openhands + 强模型 | 任务分解能力 |

## 七、学术论文风格分析

### 摘要

本研究通过大规模实证实验（5,646次运行），系统性地评估了4种代码Agent框架与10种大语言模型在CVE漏洞修复任务上的表现。研究发现，Agent工作流设计对任务成功率的影响显著，且存在明显的Agent-模型协同效应。

### 研究发现与讨论

**发现一：工作流复杂度与性能的非线性关系**

传统观点认为，更详细的指令和更复杂的工作流设计能够提升Agent的任务完成能力。然而，本研究的实证数据揭示了一个反直觉的现象：系统提示词最短的terminus-2（315词）在整体成功率上超越了提示词最长的openhands（2,400词）达12.1个百分点（27.5% vs 15.4%）。这一发现表明，在当前LLM的能力边界下，**工作流的结构化程度比指令的详尽程度更为重要**。terminus-2采用的JSON结构化输出格式，通过显式的analysis-plan-commands三段式框架，有效降低了模型的输出熵，减少了格式错误和解析失败的可能性。

**发现二：命令批处理的效率优势**

terminus-2的命令批处理机制使其在成功任务上的平均轮次（27.1轮）显著低于mini-swe-agent（35.2轮）和openhands（36.2轮）。这一效率优势在需要多文件探索的CVE任务中尤为明显。以CVE-2025-48866为例，terminus-2在Claude-4.5-Opus上仅需6轮即完成修复，而采用单命令/轮设计的mini-swe-agent则因探索效率不足而失败。**批处理机制通过减少API调用次数，不仅降低了延迟和成本，还减少了中间状态丢失的风险**，从而提升了整体任务成功率。

**发现三：Agent-模型协同效应的显著性**

本研究揭示了Agent框架与底层模型之间存在的强协同效应。以MiniMax-M2为例，该模型在terminus-2上达到30.2%的成功率，但在openhands上仅为3.3%，差异达9.2倍。类似的模式在Qwen3-Coder（9.3倍差异）和DeepSeek-V3.2（10.9倍差异）上同样存在。**这一现象表明，复杂Agent框架的有效运行高度依赖于模型的指令遵循能力（instruction-following capability）**。openhands的2,400词系统提示包含多层嵌套的条件指令和角色定义，对模型的长上下文理解和精确指令执行能力提出了极高要求。指令遵循能力相对较弱的模型在面对此类复杂提示时，容易出现指令混淆、格式错误或任务遗忘等问题，导致任务失败率急剧上升。

**发现四：任务复杂度与最优Agent的匹配关系**

通过对189个CVE任务的差异化分析，我们发现不同类型的任务存在最优Agent匹配。terminus-2在需要多文件探索和系统性分析的复杂任务（如CVE-2025-23209、CVE-2025-48866）上表现优异，而mini-swe-agent在简单的单文件修复任务（如CVE-2025-9136、CVE-2025-57764）上更为高效。这一发现支持了**"没有万能Agent"的假设**，并为实际应用中的Agent选择提供了指导：应根据任务的预期复杂度选择相应的Agent框架，而非盲目追求功能最全面的Agent。

### 研究局限与未来方向

本研究存在以下局限：（1）评估仅限于CVE漏洞修复任务，结论的泛化性有待在其他代码任务（如功能开发、代码审查）上验证；（2）部分Agent-模型组合的实验数据不完整，可能影响交互效应的估计精度；（3）成功判定基于自动化测试，可能存在假阳性或假阴性。未来研究可探索：（1）自适应Agent框架，根据任务复杂度动态调整工作流；（2）针对不同指令遵循能力模型的提示词优化策略；（3）多Agent协作在复杂软件工程任务中的应用。

### 结论

本研究通过大规模实证实验，揭示了代码Agent框架设计中的若干关键原则：简洁结构化的工作流优于冗长复杂的指令；命令批处理机制能显著提升多步骤任务的效率；Agent框架的选择应考虑与底层模型的协同效应。这些发现为代码Agent的设计和部署提供了实证依据，对于提升AI辅助软件工程的实际效果具有重要的指导意义。
